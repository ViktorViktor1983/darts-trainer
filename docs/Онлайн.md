# ONLINE_CONTEXT — Контекст разработки онлайн-режима Darts Trainer

Этот файл — дополнение к основному AI_CONTEXT. Здесь описана вся история, архитектура и планы по разработке онлайна. Прочитай его целиком, прежде чем вносить изменения.

---

## 1. СТАТУС ПРОЕКТА (Онлайн)
Успешно реализована **связь приложения с сервером (Handshake)**. Приложение умеет отправлять данные на сервер, искать игроков и обмениваться приглашениями. Синхронизация самих бросков в реальном времени пока не сделана (при старте матча запускается игра с ботом, но под именем найденного соперника).

## 3. АРХИТЕКТУРА СЕТЕВОГО ВЗАИМОДЕЙСТВИЯ
*   **`data/online/OnlineNetworkManager.kt`**: «Мост» для общения с сервером (OkHttp).
    *   `registerPlayer`: Отправляет ник и уровень (пока работает как POST-запрос, что вызывает ошибку при дубликатах).
    *   `findOpponent`: Ищет игрока (ник != мой).
    *   `sendInvite`: Отправляет приглашение, возвращает ID.
    *   `checkIncomingInvite`: Проверяет входящие "pending" приглашения.
    *   `acceptInvite`: Меняет статус на "accepted".
    *   `checkMyInviteStatus`: Проверяет, принял ли соперник приглашение.
    *   `deleteInvite`: Удаляет приглашение.
*   **`ui/online/OnlineLobbyScreen.kt`**: 
    *   Опрос сервера каждые 3 секунды (входящие приглашения).
    *   Окно ожидания (30 сек) после отправки.
    *   Окно «Принять / Отклонить» для входящих.

## 5. ЗАДАЧА НА ЗАВТРА (Первым делом)
1.  **Исправить `registerPlayer`**: Сейчас при нажатии «Начать поиск» приложение пытается создать новую запись (POST). Из-за уникального индекса это теперь вызывает ошибку, если игрок уже есть в базе. Нужно переписать функцию так, чтобы она сначала делала GET-запрос (искала игрока по нику), и если находила — делала PATCH (обновляла уровень), а если нет — POST (создавала).
2.  **Тестирование на двух телефонах**: Проверить входящие приглашения и окно ожидания.
