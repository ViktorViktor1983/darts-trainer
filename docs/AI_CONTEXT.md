Этот файл — краткая инструкция для любого ИИ (Claude, ChatGPT, Gemini и т.д.),
который подхватит работу над проектом Darts Trainer. Прочитай целиком,
прежде чем задавать вопросы.

## 1. ПРОЕКТ

**Название:** Darts Trainer (Персональный тренер по дартсу)
**Платформа:** Android, нативный Kotlin + Jetpack Compose + Room
**Репозиторий:** github.com/ViktorViktor1983/darts-trainer (ветка main)

настройки игрока, тренировки.

## 2. КАК ОБЩАТЬСЯ С АВТОРОМ

Автор — не программист, изучает Kotlin/Android по ходу дела.
Правила:

- Объясняй простыми словами, без жаргона. Если используешь термин — расшифруй.
- **Один файл — одно сообщение.** Не давай 2+ файлов в одном ответе.
- **Формат выдачи кода:**
  1. Путь к файлу (отдельным блоком, чтобы автор скопировал)
  2. Действие: «создать новый» / «заменить целиком» / «найти строку X, заменить на Y»
  3. Сам код целиком одним блоком (не разбивай на части!)
- После того как автор написал «Готово» — даёшь следующий файл.
- Если файл нужен только для просмотра — просто проси путь, не давай код.
- Не переписывай всё подряд. Меняем минимально, аккуратно.
- Если автор прислал не тот файл — вежливо скажи и попроси нужный.
- Автор часто присылает **скриншоты папок** вместо кода — это нормально.
- **ВАЖНО:** сборка в GitHub Actions запускается автоматически при сохранении
  файла. Поэтому нельзя давать «два шага в одном сообщении» — автор сохранит
  первый, пойдёт сборка с ошибкой, потому что второй файл ещё не поправлен.
- Если автор просит «обнови AI_CONTEXT» — перепиши файл целиком
  или допиши раздел «Журнал изменений» с датой.

**Что автор УМЕЕТ:**

## 5. АРХИТЕКТУРА

### Навигация
Ручная, без Navigation Compose. Работает через переменные в MainActivity.kt:

    var stage by remember { mutableStateOf("loading") }
    // welcome / onboarding / loading / main
    var screen by remember { mutableStateOf("main") }
    // экран внутри stage=main

Карта PARENT_SCREEN определяет, куда возвращает системная кнопка «Назад».

Ключевые экраны статистики:
- `"stats_menu"` → StatsMenuScreen (сетка 2x3)
- `"stats_cricket"` → StatsScreen(initialTab = 0, showTabs = false)
- `"stats_501"` → StatsScreen(initialTab = 1, showTabs = false)
- `"sector_stats"`, `"aroundclock_stats"`, `"biground_stats"`,
  `"scoreset_stats"` — собственные экраны статистики, возвращаются
  системной кнопкой «Назад» в `stats_menu`.

### Данные
Room Database. Для каждой игры — отдельная база:
`Game501Database.kt`, `CricketDatabase.kt`, `SectorDatabase.kt`,
`AroundClockDatabase.kt`, `BigRoundDatabase.kt`, `ScoreSetDatabase.kt`.
Внутри каждого файла: Entity, Dao, Database, Repository.

### Хранение сложных структур
Игроки и их метрики хранятся строками через разделитель «|» (по игрокам)
или «,» (внутри одного игрока). Пример: ppr = "62.14|48.30".
При чтении парсится функциями parseStringList, parseIntList, parseDoubleList.

### Сохранение игр
**ВАЖНО:** сохранение в базу делается на уровне MainActivity, а НЕ внутри
экранов. Причина: `rememberCoroutineScope()` внутри экрана отменяется
при закрытии экрана — если экран запустил `saveGame` и сразу закрылся,
задача отменяется, до базы ничего не долетает.

Правильная схема:
- Экран после завершения игры вызывает `onFinish(...)` с данными.
- MainActivity через свой `scope` (живёт долго) вызывает `saveGame`.

Применено в: ScoreSetGameScreen (последний фикс), AroundClock — по
аналогии. Проверить Sector, BigRound.

### Стиль
Jetpack Compose, тёмная тема. Карточки — TileBg и TileBgDark.
Акценты — Accent, GoldAccent.

## 9. ПРОЕКТНЫЕ РЕШЕНИЯ

- 16 уровней по разрядам Минспорта (Ю3 → МС), но названия в x01
  сделали без привязки к разрядам (Разрядник, Мастер, Супер мастер,
  Легенда).
- Уровень определяется по 2 из 3 параметров: Сектор 20, Набор очков,
  Большой раунд. Удвоения — отдельный приоритет, на уровень не влияют.
- Понижение уровня: если 2 из 3 параметров упали на 10 тренировках.
- Разминка 4 фазы: мышцы → траектория → кучность → прицеливание.
- Структура тренировки: разминка → блок 1 (слабое место) → блок 2 →
  блок 3 (501/Крикет) → силовые (гантели 1 кг).
- Контрольная тренировка — каждая 10-я, сдача нормативов.
- Отложенные даблы возвращаются в начале следующей тренировки.

### Метрики на карточках статистики
- **501**: средний PPR за всё время (исключая игры со STRAIGHT_OUT).
- **Крикет**: средний MPR за всё время.
- **Сектор**: максимум totalScore (лучшая сессия из 30 дротиков).
- **Большой раунд**: максимум totalScore.
- **Набор очков**: максимум totalScore (10 подходов).
- **Кругосветка**: минимум totalDarts среди completed = true
  (меньше = лучше).

## 13. ЧАСТЫЕ ОШИБКИ АВТОРА (и как их ловить)

1. **Код попадает не в тот файл.** При создании нового файла в GitHub
   путь иногда подставляется от предыдущего открытого файла. Проверяй
   первую строку `package ...` — она должна соответствовать пути.

2. **Копируется не весь файл.** Тогда появляются сотни ошибок
   «Unresolved reference» или «Redeclaration». Лечится заменой файла
   целиком.

3. **Забыл сохранить правку.** Тогда сборка не меняется.

4. **Слишком много ошибок в логе.** Не проси присылать всё —
   первых 30–40 строк достаточно, дальше идут повторы.
