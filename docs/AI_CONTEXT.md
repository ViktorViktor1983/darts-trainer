## 2. КАК ОБЩАТЬСЯ С АВТОРОМ

Автор — не программист, изучает Kotlin/Android по ходу дела.
Правила:

- Объясняй простыми словами, без жаргона.
- **ОДИН ФАЙЛ — ОДНО СООБЩЕНИЕ.** Железное правило.
- **Формат выдачи кода:**
  1. Путь к файлу в отдельном блоке кода (чтобы легко копировалось).
  2. Действие: «создать новый» / «заменить целиком».
  3. Сам код целиком одним блоком.
  4. **В САМОМ КОНЦЕ обязательно писать маркер:** `Конец файла.`
- Давай код **целиком**, не разбивай на части.
- **АВТОР ПРОСИТ: «путь и файл целиком» — это принципиально.**
  Даже для правки в 2 строки — давай весь файл.
- Если файл уже собран — не переписывай, но всё равно давай целиком.
- **СНАЧАЛА СОГЛАСУЙ ЛОГИКУ, ПОТОМ ДАВАЙ КОД.** Автор раздражается, если ты пишешь код без его одобрения (он может забраковать логику).
- Автор часто присылает **скриншоты** — это нормально.
- **ВАЖНО:** сборка в GitHub Actions запускается автоматически после сохранения.
  Нельзя давать два шага в одном сообщении.
- Если автор просит «обнови AI_CONTEXT» — перепиши файл целиком.
- **НЕ использовать вложенные блоки кода (тройные бэктики внутри тройных)** —
  это ломает копирование.
- **НЕ упоминать слово Telegram** (автор использует другой мессенджер).
- Автор задаёт вопросы **по одному**, отвечай так же.
- Если автор прислал не тот файл — вежливо скажи и попроси нужный.
- **Автор может не понимать техническую часть** — ты решаешь, как лучше
  технически, а он задаёт логику «как должно работать».

## 5. АРХИТЕКТУРА И ЛОГИКА

### Периоды
С момента последнего экзамена. При сдаче экзамена (`clearStatisticsAfterNormatives`) данные не удаляются, а начинается новый период (`periodId + 1`). Старые данные остаются в БД.

### Статистика
Собирается в `detailsJson` (например, `ppr=71.5;c180=2;c140=1`).
В `DisciplineStatsScreen` строятся графики (самописный Canvas).

### Психология
8 упражнений (Текст, Дыхание 4-4-7, Один дротик, Туннельное зрение).
Даются по 3 штуки за тренировку, цикл сдвигается (хранится в `InventoryStorage`).

### Силовые
9 упражнений (6 своих, 2 с гантелями, 1 с резинкой).
При входе в блок выскакивает `InventoryDialog`, где игрок отмечает инвентарь. Список фильтруется. Даются по 3 штуки, цикл сдвигается.

### Свободная игра с другом
Реализована возможность сыграть с другом в 501/Крикет через `FreeRouletteScreen` (при включении тумблера «Играть с другом»).

### Онлайн-игра (Бэклог)
Решено делать через **Firebase** (Firestore + FCM).
- Отказ от мессенджеров (MAX/Telegram).
- **Матчмейкинг:** Игрок нажимает «Найти соперника» → запись в Firestore → поиск соперника с похожим уровнем → создание комнаты.
- **Синхронизация:** Броски и счет в реальном времени (Snapshot Listeners).
- **Уведомления:** Push через Firebase Cloud Messaging.
- **Статистика:** Сохраняется в локальную БД.

## 6. ГДЕ МЫ ОСТАНОВИЛИСЬ (Важно!)

Мы только что успешно провели «генеральную уборку» (вынесли роутеры), добавили графики, психологию и силовые упражнения. Сборка зелёная.

**ТЕКУЩАЯ ПРОБЛЕМА (ОБСУЖДАЕТСЯ):**
Игрок проходит основную тренировку (например, 3 упражнения из плана). Заканчивается блок. Появляется экран итогов.
Игрок хочет **продолжить тренировку** (добавить еще упражнения в основной блок), а не переходить на психологию/силовую и не заканчивать.
ИИ предложил добавить кнопку «+ Добавить упражнение», но **автор забраковал реализацию и попросил сначала обсудить логику**.

**Варианты логики, которые нужно обсудить с автором:**
1.  **Кнопка «+ Добавить» (отклонено):** На экране итогов кнопка, которая докидывает упражнение.
2.  **Автоматически по времени:** Если время тренировки не вышло, программа сама подкидывает следующее упражнение, пока не кончится время.
3.  **Галочка в настройках:** «Не ограничивать количество упражнений» — программа крутит их по кругу, пока не выйдет время.
4.  **Свой вариант автора.**

**СЛЕДУЮЩИЙ ШАГ:** Обсудить с автором эти варианты, выбрать лучший, согласовать логику и только потом писать код.
