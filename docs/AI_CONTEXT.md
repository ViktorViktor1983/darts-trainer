# AI_CONTEXT — шпаргалка для нового ИИ-ассистента

Этот файл — краткая инструкция для любого ИИ (Claude, ChatGPT, Gemini и т.д.),
который подхватит работу над проектом Darts Trainer. Прочитай целиком,
прежде чем задавать вопросы.

## 2. КАК ОБЩАТЬСЯ С АВТОРОМ

Автор — не программист, изучает Kotlin/Android по ходу дела.
Правила:

- Объясняй простыми словами, без жаргона.
- **ОДИН ФАЙЛ — ОДНО СООБЩЕНИЕ.** Железное правило.
- **Формат выдачи кода:**
  1. Путь к файлу в отдельном блоке кода (чтобы легко копировалось).
  2. Действие: «создать новый» / «заменить целиком».
  3. Сам код целиком одним блоком.
  4. **В САМОМ КОНЦЕ обязательно писать маркер:** `Конец файла.` (чтобы автор мог проверить, что текст не оборвался при копировании).
- Давай код **целиком**, не разбивай на части.
- **АВТОР ПРОСИТ: «путь и файл целиком» — это принципиально.**
  Даже для правки в 2 строки — давай весь файл. Так меньше шансов на ошибку.
  Не предлагать точечные правки «замени строку X» — автор так не работает.
- Если файл уже собран — не переписывай, но всё равно давай целиком.
- Автор часто присылает **скриншоты** — это нормально.
- **ВАЖНО:** сборка в GitHub Actions запускается автоматически после сохранения.
  Нельзя давать два шага в одном сообщении.
- Если автор просит «обнови AI_CONTEXT» — перепиши файл целиком.
- **НЕ использовать вложенные блоки кода (тройные бэктики внутри тройных)** —
  это ломает копирование текста.
- Автор задаёт вопросы **по одному**, отвечай так же.
- Сначала согласуй логику, потом давай код.
- Если автор прислал не тот файл — вежливо скажи и попроси нужный.
- **Автор может не понимать техническую часть** — ты решаешь, как лучше
  технически, а он задаёт логику «как должно работать». Доверяй ему в логике,
  он доверяет тебе в технике.

**Что автор УМЕЕТ:**
читать текст, скриншоты, фото; писать код Kotlin/Compose/Room
(копирует в GitHub вручную); собирать APK через GitHub Actions.

**Что автор НЕ УМЕЕТ:**
открывать ссылки/GitHub/интернет за ИИ, генерировать картинки,
загружать файлы в GitHub за ИИ.

**Что раздражает автора:**
- когда ИИ просит «найди строку X в файле» — он предпочитает получить
  файл целиком и заменить его тоже целиком;
- когда файл слишком большой (2000+ строк) — просит разбить на части;
- когда кнопка в диалоге уходит за пределы экрана.

### data/ — данные

**data/SettingsStorage.kt** — имя владельца телефона, настройки.

#### data/game501/ (Game501Database v5)
Модели, логика, боты, симулятор, чекауты. Важно: Player501 содержит
счетчики `matchCount180`, `matchCount170plus` и т.д., а также `listOfFirst9Ppr`.

#### data/cricket/ (CricketDatabase v4)
Модели, логика, боты.

#### data/sector/, data/biground/, data/scoreset/, data/aroundclock/
Отдельная БД для каждой игры.

#### data/freerecords/ — рекорды свободной игры

#### data/training/ — тренировочный раздел

**TrainingDatabase.kt** — **версия 7**.
Таблицы: training_sessions, exercise_results, postponed_doubles,
weakness_snapshots, potential_snapshots, control_matches,
training_records, training_checkouts, **darts_history** (новая в v6).
В v7 добавлено поле `periodId` в таблицы сессий и результатов.
Репозиторий `TrainingRepository(db, context)` теперь требует context для работы с периодами.

**TrainingPeriodStorage.kt** — хранит номер текущего периода.
При сдаче экзамена (`clearStatisticsAfterNormatives`) он не удаляет данные,
а просто вызывает `startNewPeriod()`, увеличивая счетчик.
Все новые игры пишутся с новым `periodId`.

**TrainingStatsAnalyzer.kt** — анализ. Берет только данные ТЕКУЩЕГО периода.
Считает 4 параметра, 2 комплекса, прогресс до экзамена (по 5 записей),
темп (avgMinutesByExercise), парсит `detailsJson` для поиска худших секторов.
Для 501 вытаскивает 180, 140 и т.д. из `detailsJson`.

**TrainingPlanner.kt** — генератор программы.
Учитывает слабые места, вставляет «Точечную работу» первым упражнением,
если её не было в этом периоде.

**DartsNorms.kt** — 16 уровней.
PPR (501) и MPR (Крикет) исправлены на реальные значения (MPR max = 9.0).

### ui/ — экраны

**MainMenuScreen** — главный экран. Показывает PPR, % удвоений и кнопку
«Подробная статистика». При нажатии ведет на `DetailedStatsScreen`.

**ui/training/**
- **DetailedStatsScreen.kt** — хаб аналитики. Кнопки прогресса, дротиков,

  Для 501: фильтры по времени (неделя/месяц/все время), графики PPR, Удвоений,
  Первых 9 и Мусорных рук (<57). Данные берутся из `detailsJson`.
- **FreeRouletteScreen.kt** — рулетка + тумблеры «Без повторов»,
  «Выбрать самому» и «С играть другом» (на карточках 501/Крикета).

  TargetedPracticeScreen (Снайпер) и другие экраны.

## 5. АРХИТЕКТУРА И ЛОГИКА

### Периоды
С момента последнего экзамена. Вся статистика (кроме рекордов и дротиков)
считается только за текущий период. Старые данные хранятся в БД с `periodId < current`,
их можно будет смотреть в будущем.

### Экзамен
Открывается, когда все 8 упражнений набрали по 100% (по 5 записей).
При успехе статистика не удаляется, а начинается новый период.

### Онлайн-игра (Бэклог)
Решено делать через **Firebase** (Firestore + FCM).
- Отказ от мессенджеров (MAX/Telegram) из-за лимитов и задержек.
- В приложении будет встроенное лобби.
- **Матчмейкинг:** Игрок нажимает «Найти соперника». Приложение ищет
  в Firestore свободного игрока с похожим уровнем.
- **Комната (Room):** При соединении создается комната. Броски и счет
  синхронизируются в реальном времени через Firestore (Snapshot Listeners).
- **Уведомления:** Встроенные Push-уведомления через Firebase Cloud Messaging.
- **Статистика:** Результаты игры сохраняются в локальную БД (Room) как тренировка.
